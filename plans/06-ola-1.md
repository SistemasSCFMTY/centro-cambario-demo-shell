## Foundation deliverables
- **Libraries:** `@tanstack/angular-table` and the Spartan helm components the screens need (at least table, tabs, dialog, popover, select, textarea, skeleton; generate them into `libs/ui` like the existing ones, with tsconfig aliases).
- **Shared components** (`src/app/components/`), per `01` Shared building blocks:
  - data table (helm table + TanStack): sorting, server-side paging, row click + `.row-action`, skeleton and flat empty states, `font-data` numerals
  - status pill (fixed semantic set), lead cell (`.lead-avatar` / `.lead-thumb`), key/value field grid, filters popover with URL-persisted filters/page
  - detail page shell (header card + tabs) with the mandatory **Auditoría** tab component
  - sticky action bar for forms
- **Utils** (`src/app/utils/<topic>/`, each with a spec): money and currency formatting (MXN base, ISO 4217), dates, URL filter state.
- **Domain data** (`src/app/data/`): interfaces and types for divisa, sucursal, caja/bóveda, cajero (staff), cliente (summary + what the detail needs), operación, tipo de cambio, registro de auditoría. Fixtures, deterministic, with clearly fake data:
  - divisas from `plans/catalogos/divisas.json` (MXN + USD, EUR, JPY, CNY, KRW)
  - the centro cambiario and three sucursales (`04` Fixtures: real CNBV localidad keys, one in Baja)
  - cajeros, cajas and bóvedas per sucursal
  - clientes (personas físicas and morales, mixed estatus) and operaciones over the last weeks that reference them, consistent with the demo's rules (FIX, USD equivalent, levels, Relevante, authorization)
- **Simulated API per module:** `interceptors/simulacion-api/manejadores/<modulo>.manejador.ts`, registered in one list. `ApiSimulada` dispatches to them. List endpoints take page/size/sort/filter query params and answer like a paged server. Each module keeps its API paths in `data/constants/<modulo>.constants.ts`.
- **Routes per module:** `app.routes.ts` loads `modules/<modulo>/<modulo>.routes.ts` via `loadChildren` for the five screens. Each routes file provides its own NGXS states (`provideStates`). The foundation leaves a stub routes file (placeholder page) and a stub handler for each of the five.
- Green `ng build` and `ng test`.

## Ownership during the screens phase
Writers run at the same time in one working tree, so each owns only its own files:
- **Yours:** `modules/<modulo>/**`, `store/<modulo>/**`, `services/<modulo>/**`, `interceptors/simulacion-api/manejadores/<modulo>.manejador.ts`, `data/constants/<modulo>.constants.ts`, and **new** files in `data/{interfaces,types,dto,fixtures}/` named for your module.
- **Not yours:** everything else, including shared components, utils, `styles.css`, `app.routes.ts`, `app.config.ts`, the foundation's domain files and the plans. If you need a change there, put it in your result as a shared-change request instead.
- **Checks:** run `npx tsc -p tsconfig.app.json --noEmit` and Prettier on your files. **Don't run `ng build`, `ng test` or `ng serve`** in this phase (they'd collide). Ignore type errors in files you don't own.
- Don't commit.
